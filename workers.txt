Module Name:
Alert & notification workers

Worker Name:
1. alertDispatchWorker
2. engineHeartbeatWorker
3. kiteConnectionMonitorWorker
4. tradeLogWriterWorker

Queue Name:
1. alertDispatchWorker
2. engineHeartbeatWorker
3. kiteConnectionMonitorWorker
4. tradeLogWriterWorker

Job Type:
1. Queue
2. Cron
3. Event
4. Queue

Frequency:
1. On alert event
2. Every 60 sec
3. On disconnect event
4. On every log event

Business Purpose:
1. Listens to alert queue — writes each alert to alerts table and pushes it to the frontend via WebSocket alert:new event. Handles deduplication to avoid flooding the same alert repeatedly.
2. Each engine (sector, tracked, invested, exit) emits a heartbeat event every 60 seconds — stored as last_run in DB and pushed via system:engine_heartbeat WebSocket. If heartbeat missing for 2+ intervals, creates critical alert.
3. Monitors Kite WebSocket Ticker connection health — detects disconnect events and triggers reconnect with exponential backoff (1s → 2s → 4s → max 30s). Creates alert if reconnect fails after 5 attempts.
4. Dedicated async writer for trade_logs table — all engines push log events to this queue instead of writing directly to DB. Prevents DB write contention during high-activity periods when multiple engines fire simultaneously.
